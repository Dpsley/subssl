subssl

TLS certificate inventory and monitoring for NIC.RU DNS zones. Build an inventory from the DNS zone you actually operate, then detect certificate expiry, hostname mismatches, connection failures, and other TLS problems before users do.

View on GitHub Quick start Releases

What subssl does

DNS-driven inventory

Uses your NIC.RU DNS zone as the source of truth instead of performing random internet-wide hostname enumeration.

TLS health checks

Checks certificate expiry, issuer details, hostname matching, and TLS connection failures on the ports you choose.

Internal DNS support

Queries local resolvers first, then falls back to public DNS when local resolution has no answer.

Monitoring outputs

Exports JSON and CSV reports, publishes Prometheus metrics, and includes Grafana dashboard and alert assets.

subssl

Designed for operational TLS visibility

subssl is intended for operators who want a repeatable TLS/SSL certificate inventory tied directly to the DNS names they manage. It is especially useful when certificate monitoring must cover both public and split-horizon or internal DNS names while still feeding existing Prometheus and Grafana workflows.
