How it works

From DNS zone to TLS visibility

subssl uses the DNS zone you manage as its source of truth, resolves hosts as your environment does, probes TLS, and feeds the resulting health data into monitoring.

◎

1. Discover

Import the zone apex and direct, user-facing hostnames from NIC.RU.

▤

2. Scan TLS

Resolve endpoints, connect on configured ports, and inspect certificate state.

▥

3. Export metrics

Write JSON/CSV reports and publish the current snapshot to Prometheus.

♢

4. Get alerted

Use Grafana and bundled alert rules to surface expiry and TLS issues.

Monitoring stack

Works with the tools you already use

subssl publishes operational certificate data instead of locking it inside a separate web service.

● PrometheusPushgateway metrics for host, endpoint, port, certificate dates, issuer type, and safe TLS errors.
◉ GrafanaBundled dashboard and alert assets for certificate expiry, probe failures, and hostname mismatch visibility.
Installation

Quick start on Debian / Ubuntu

Install the isolated runtime and expose the subssl command system-wide.

$ git clone https://github.com/Dpsley/subssl.git
$ cd subssl
$ chmod +x install.sh
$ sudo ./install.sh
$ subssl
